# Slide 2 — Le problème rencontré dans les programmes IA

## Trop de PoC, pas assez de décisions industrialisables

Les freins les plus fréquents :

- cas d’usage mal formulés ;
- sponsor absent ;
- KPI non défini ;
- données non prêtes ;
- Shadow AI ;
- sécurité et RGPD traités tardivement ;
- fournisseur non évalué ;
- risques / impacts non formalisés ;
- absence de human oversight ;
- responsabilité de mise en production floue ;
- faible continuité entre PoC et run.

**Conséquence :**
les équipes Data & IA peuvent livrer un bon prototype qui ne passe jamais en production.

- KPI absent.

Après Sprint :
- problème métier ;

- risques ;
- human oversight ;
- architecture cible ;
- décision ;
- roadmap.

**Bénéfice :**

# Slide 9 — Le Governance Gate avant la production

## « Techniquement prêt » ne signifie pas « gouverné »

Avant passage en production, vérifier si applicable :

- classification complétée ;
- risques traités ;
- impact assessment ;
- sécurité / privacy ;
- vendor review ;
- human oversight ;
- contrôles ;
- preuves ;
- décision formelle ;
- owner et review date.

**Visuel :**
`PILOT → [GOVERNANCE GATE] → PRODUCTION`

# Slide 10 — Le Change & Reassessment Engine

## Un modèle ou un dataset peut changer sans que le projet soit “terminé”

Triggers :

- nouveau modèle ;
- nouveau dataset ;
- changement de finalité ;
- nouveau fournisseur ;
- plus d’autonomie ;
- nouvelle population ;
- nouveau territoire ;
- évolution sécurité.

AIGMS oriente alors vers :

- no reassessment ;
- partial reassessment ;
- full reassessment.

**Bénéfice SEI :**
gérer proprement les évolutions post-production.
